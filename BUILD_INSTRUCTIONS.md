# DumbDock Amp - VST3 (AMP-001 "Dumb 1" + AMP-002 "Dock", 2 cabs with 1-2 mics each)

NO CODING NEEDED: use the ready-made installer (Windows folder: Install-DumbDockAmp.exe).
For macOS see HOW_TO_GET_INSTALLERS.txt (click-only, uses GitHub to build the installer for you).
Everything below is only for people who want to compile the source themselves.

## Easiest for compile-it-yourself: the installer script
    python3 setup_wizard.py            # interactive: checks tools, builds, installs, verifies
    python3 setup_wizard.py --check    # only check prerequisites
    python3 setup_wizard.py --yes --juce-dir /path/to/JUCE
Options: --dry-run --standalone --skip-build --build-dir --install-dir. Log: setup_wizard.log.

## Manual build
Needs: CMake >= 3.22, a C++17 compiler (VS 2022 / Xcode / gcc), Python 3, and JUCE 7.0.12.
CMake uses -DJUCE_DIR=..., or ./JUCE, or downloads JUCE 7.0.12 automatically (internet needed).

    cmake -B build -DCMAKE_BUILD_TYPE=Release
    cmake --build build --config Release -j

Linux also needs: libasound2-dev libfreetype-dev libfontconfig1-dev libx11-dev libxext-dev libgl-dev.
Copy the .vst3 from build/DumbDockAmp_artefacts/Release/VST3/ to:
Windows C:\Program Files\Common Files\VST3 | macOS ~/Library/Audio/Plug-Ins/VST3 | Linux ~/.vst3
Then rescan plugins in Reaper (Options > Preferences > Plug-ins > VST > Re-scan).

## Inside the plugin
A short welcome popup (the two amps, their options, the cabinets and mics) shows when the window opens;
tick "Don't show this again" to hide it, the "?" button brings it back. There is no setup wizard in the plugin.

AMP-001 "Dumb 1": four channels (1 Clean / 2 Crunch / 3 Lead / 4 Ultra), each with its own GAIN, BASS, MID, TREBLE.
Shared: CHAR, PRES, VERB, GATE (noise gate, fully left = off), MASTER, six EQ sliders, POWER TUBE.
"Active channel" selects which channel plays (a frame marks it). CHAR is a bright-bleed control: it adds treble
that stays when the volume of the preamp is turned down (like a treble-bleed capacitor), so it matters most at low GAIN.

AMP-002 "Dock": channel A Pristine / B Chime, each with its own GAIN, BASS, MID, TREBLE; PRES, VERB, MASTER, STANDBY.

Cabinets (both panels always visible, the active cab is highlighted): MIC 1 (type, POS, DIST, LVL, PAN), optional MIC 2
(on, type, POS, DIST, LVL, PAN, phase invert) and CAB LVL, per cab. CAB OFF (top bar) bypasses the built-in cabinet so you can
follow the plugin with your own IR loader. Details: docs/CAB_AND_MICS.md.

## What GAIN does (see VOICING_NOTES.md)
GAIN is the pot that feeds the drive stages: it changes how hard the tubes are driven (and, like on the real amps, the
level rises with it); it is not an interface-style trim. Each mode / channel has its own range:
  AMP-001 1 Clean   : very high headroom, only starts to break up at GAIN 8-10
  AMP-001 2 Crunch  : clean to GAIN 3, crunch from GAIN 5, rhythm distortion at 7-10
  AMP-001 3 Lead    : one extra cascaded gain stage, saturated from GAIN ~4
  AMP-001 4 Ultra   : two extra cascaded stages, saturates from a quiet DI already at GAIN 3-5
  AMP-002 A Pristine: clean up to pedal levels
  AMP-002 B Chime   : clean to GAIN 5, walks into edge-of-breakup at 8-10 (a little more gain than the first version)
The make-up tables (Source/Amps/Calibration.h) are generated by tests/calibrate.sh; the per-mode voicing constants
sit in the tables at the top of Amp001Model.cpp / Amp002Model.cpp. They are voicing choices, not schematic values.

## Safety behaviour
The output cannot clip: a look-ahead limiter (ceiling -1 dBFS, 1 ms look-ahead) turns hot signals down smoothly (docs/GAIN_STAGING.md).
NaN/Inf/runaway is detected and reset; fade-in after resets; structural switches (mode, channel, power tube, standby)
are applied while the output is ducked, so no pops; no allocation on the audio thread; any block size; 44.1-192 kHz.
Runs oversampled to ~192 kHz internally (4x at 44.1/48 kHz, 2x at 88.2/96 kHz, none at 176.4 kHz and up). Reported
latency = oversampler + 1 ms limiter look-ahead (87 samples at 48 kHz). Stereo input is summed to mono; output is stereo
(the two mics can be panned; a mono track gets the fold-down).
CPU, Linux sandbox, 48 kHz, one core: about 16 % with one mic, 17 % with two mics (26 % while dragging mic knobs).

## Honest limits
- Tube stages (Koren triodes, LTP phase inverters) and the TMB stack are solved from the schematic values.
  The power stage and output transformer are behavioural models, not circuit solves; sag is approximated.
- EQ gyrators are modelled as peaking filters; presence is a high-shelf approximation.
- Cabinets are synthesised from a physical model, not measured IRs; the five microphone models are approximations drawn from
  published descriptions, not measurements of real microphones. Use CAB OFF + a real IR if
  you want a measured cabinet.
- NOT on the schematics (added later): the Bass/Mid/Treble stack on AMP-001, the extra gain stages of modes 3-4, per-mode
  input pads / tightening / interstage attenuators / grid stoppers, the two Dock channel voicings, the reverb algorithms,
  oversampling, the MASTER loudness law, the safety limiter, the noise gate, the per-channel controls, the cab/mic model.
  See VOICING_NOTES.md.
- Everything was tuned with measurements; nobody has listened to it yet. Expect to adjust by ear.
- Assumed (not in the schematics): TMB slope resistor 56k and treble cap 250pF (sheet says 4.7nF),
  LTP tail rail -60 V, EQ board loss, "Character" bright bleed.
- SW1 mode order follows your sketch, which is reversed vs. the schematic PDF; swap CK_MODE in
  Source/Amps/Amp001Model.cpp if you want the PDF order.
- Built and tested on Linux only. Windows/macOS and .github/workflows/build.yml are untested here.
  The GUI was rendered headlessly, not tried by hand in Reaper.
